# VCT Connect browser capture

This is a local, unpacked Chrome extension for a buyer viewing a supported 1688 offer or Taobao item/shop. Clicking **Analyze this page** selects visible evidence and sends it to the signed-in VCT Connect account. Version 0.4.1 uses guided 1688 product → company capture: the user opens the linked shop and completes login/CAPTCHA before clicking Analyze again. Optional 1688 access is requested; the user gesture also grants activeTab capture on the company page. Taobao uses the existing `activeTab` capture path.

## Development setup

1. Put the existing Clerk publishable key in `frontend/apps/web/.env.local` as `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` (the web app already uses this file). Use the same Clerk development instance for web and extension.
2. From the repository root, run `npm install --prefix frontend --legacy-peer-deps`, then `npm run build --prefix frontend/apps/extension`.
3. Enable Clerk **Native API**. Register the extension's development origin by running `.\.venv\Scripts\python.exe scripts\configure_clerk_extension_origin.py` from the repository root. The script reads the ignored `.env.clerk`, preserves existing allowed origins, and registers `chrome-extension://klggcepemjjbphjclpiabgpfgdbgiljj`.
4. Add that exact origin to the backend's `CLERK_AUTHORIZED_PARTIES` alongside the web origin, then restart the backend. The repository's `.env.example` shows the format.
5. Open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked**, and select `frontend/apps/extension/build`. Confirm Chrome shows extension ID `klggcepemjjbphjclpiabgpfgdbgiljj`.
6. Start the existing database, backend, and web app. The local extension build calls `http://127.0.0.1:3000`. A deployment build can set `VCT_WEB_ORIGIN` to its HTTPS origin before running the build command; the deployed backend must also allow the stable extension origin.

Open the extension and choose **Sign in on VCT Connect**. Complete sign-in in the web tab using the same Chrome profile, then return to a supported source page and reopen the popup. The popup checks the active page before exposing **Analyze this page**; signed-out or unsupported-page states never expose the enhanced-analysis action. Supported forms are `https://detail.1688.com/offer/<id>.html`, `https://item.taobao.com/item.htm?id=<id>`, and numeric `https://shop<id>.taobao.com` / `https://shop<id>.world.taobao.com` shops with `/`, `/index.htm`, or `/category.htm`. Tracking parameters are removed; duplicate item IDs, credentials, ports, fragments, mobile pages, Tmall, and short links are unsupported. Clerk Sync Host shares the web session with the extension. Development builds sync from the exact web origin (default `http://127.0.0.1:3000`); production builds sync from the Clerk Frontend API host. Do not use `localhost` when this build is configured for `127.0.0.1`.

Click **Analyze this page**. The action re-checks the active page identity and obtains a fresh Clerk token before any enhanced-evidence request. After company capture is finalized (or product-only completion is chosen), the extension opens the web result in a new tab and loads the owner-scoped status through the shared VCT API client/contracts. **Open web result** remains available to reopen it. If result loading fails after submission, use **Reload last result**; the last analysis ID, source URL, and Clerk owner ID are stored locally so recovery is scoped to the signed-in account. If the source shows only a challenge or the chosen fields are absent, the result records a parse failure without a supplier snapshot.

After rebuilding, reload the extension from `chrome://extensions` before testing. Clerk's SDK uses the `cookies` permission to sync the VCT Connect session from the configured host; no source-site cookie is read. If the popup reports that sign-in is taking too long, open VCT Connect, confirm web sign-in completed, then close and reopen the popup.

For guided 1688 capture, keep migration `0017_extension_collection_jobs` applied and restart API and the continuous worker. Click **Analyze this page** on the product with its reviews loaded. The extension reserves one analysis/quota slot, extracts product evidence, downloads cleaned product HTML and uploads it. A green outline and instruction card identify the supplier/company name to click. The popup also offers **Open linked company page**. No supplier tabs are opened or closed automatically.

Open that linked shop yourself, complete any login/CAPTCHA and wait for its company introduction to load. Reopen the extension and click **Analyze this page** again. The active shop must match the product's supplier link; login/challenge pages and other suppliers cannot be captured. The extension downloads cleaned shop HTML, uploads combined product/company evidence under the same analysis ID, then opens the result for assessment. For factory details, the user may navigate from the shop to **Factory profile / 工厂档案** before the second Analyze click. That profile must have a matching canonical identity and a visible backlink to the product's company. Its selected claims and cleaned HTML enter the same analysis; a shop capture is never invented. The page not captured remains an explicit limitation. Factory profiles are not automatically traversed.

Guided reservations allow 30 minutes for user interaction. Reopening Chrome or the popup restores the pending owner-scoped capture. **Finish with product evidence only** submits partial evidence immediately. If the user abandons collection, the continuous worker falls back to the stored product after 30 minutes with explicit timeout limitations. Legacy automatic clients retain their 60-second deadline. Lost begin responses retry the same durable reservation; lost finish responses retain the exact final payload for **Retry saved upload**, without recapture or another quota slot. Old reports remain immutable.

Cleaned HTML copies are saved to `Downloads/VCT Connect/<analysis ID>/product.html` and `shop.html`. Chrome settings may prompt for locations; disk-download failures do not prevent upload. HTML limits remain 2 MB UTF-8 per source and 8 MB JSON transport, with an independent 32 KB selected-field cap and 48 KB normalized assessment input. The backend supplements product description/packaging/size/warning/services/attributes and the shop's company introduction, preserves loaded review multiplicity and records source URLs/hashes/statuses. Public markup is rebuilt from allowlisted regions, excluding scripts, hidden/account content, buyer identities and remote media. Only normalized additions enter the LLM prompt; raw HTML is not retained in reports. Taobao retains its selected-field path.

The 1688 selection retains its existing supplier, title, and price fields. Taobao items select the product title under ItemTitle/MainTitle, the shop name and contextual metrics, and review bodies under Comments/Comment/contentWrapper/content. Taobao shops select the shop name and at most 20 product links/titles inside the audited shop shelf. Inactive and hidden nodes are excluded; unverified shop age and evaluations remain unknown. The standalone selected-field capture path contains source identity, optional canonical URL and these values, within 16,384 UTF-8 bytes. The linked 1688 path also includes the bounded cleaned HTML described above. Review text is bounded and its original extent is included. Source credentials, cookies, tokens, storage, scripts, request headers and page globals are excluded from evidence capture; original full-page HTML is not uploaded. Results are labeled `EXTENSION_ENHANCED` / `EXTENSION_DOM` with user-provided browser provenance. Successful/partial captures queue assessment and reporting; configure the worker's server-only `YESCALE_API_KEY` for this path. The popup displays Risk, Confidence and Coverage only from an authorized persisted report. Missing reports and insufficient evidence never imply low risk. Reopening the popup restores the current owner's last analysis and loads its progress/verdict automatically; **Reload last result** remains a recovery action.

Saved HTML can also be imported through the signed-in web page using the matching supported source URL. Uploads are limited to 2,000,000 original bytes; 1688 requires UTF-8, while Taobao supports UTF-8 and GBK-family declarations. Conflicting or unsupported encodings are rejected. Uploads retain the original-byte hash, import time, and unknown original capture time, with `ACCOUNT_PUBLIC` / `USER_UPLOAD` provenance.

Successful/partial imports queue the same assessment/reporting path without recrawling the source page. Alibaba saved HTML and browser capture remain unsupported. See [the buyer acceptance guide](../../../END_USER_TEST.md) for concrete report/history/Watchlist and extension checks. Automated popup contracts do not replace a real Chrome/Clerk session-sync test.

If Windows reserves API port 8000, start Uvicorn with `--port 8080` instead. In the web app's PowerShell terminal, set `$env:API_INTERNAL_ORIGIN='http://127.0.0.1:8080'` before `npm run dev --prefix frontend`. The extension still uses web port 3000. Check reserved ports with `netsh interface ipv4 show excludedportrange protocol=tcp`.

The manifest's public `key` fixes the unpacked extension ID. It is not a signing key or a credential. Keep any private signing key for future store distribution outside the repository.

Version 0.4.1 fixes lowercase SVG/foreign-namespace leakage into cleaned HTML. A definitive 422 rejection discards invalid cached evidence; retry captures fresh product evidence. Ambiguous network responses retain the original reservation for safe replay.


## Guided HTML capture — 0.5.0

Analyze a 1688 product, then visit its linked shop. If a CAPTCHA overlay appears, close it with X yourself; when the company introduction is visible, open the extension and choose **Save shop HTML**. This captures a cleaned public snapshot and starts its download while retaining the same pending product analysis. The shop capture does not finalize the analysis.

Follow the highlighted **Factory profile / 工厂档案** control. Close any dismissible overlay and choose **Save factory HTML & analyze** in the extension. Matching product/shop/factory evidence uploads together and opens the result. **Finish with captured product & shop** is available when factory evidence is unavailable. The 30-minute reservation remains unchanged; an abandoned collection falls back to the server-stored product only.

Guidance appears on matching page load or when the popup opens. A page visit alone does not capture or download data. No CAPTCHA solution or automated challenge dismissal is performed. Empty company regions remain unavailable. Canonical/profile backlinks bind sources to the same supplier; JavaScript navigation labels can be highlighted even without an href.

Downloads start under `Downloads/VCT Connect/<analysis ID>/product.html`, `shop.html`, and `factory.html`. Browser download failure is reported without discarding uploadable HTML. Scripts, account controls, hidden content and media remain excluded; source-byte and transport caps remain enforced. Local build directory: `frontend/apps/extension/build`, target `http://127.0.0.1:3000`. Keep the local web/API/database/worker running.
